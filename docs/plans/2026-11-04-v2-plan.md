## 一、方案的一句话

**把「录入一整张表」拆成「收件 → 加工」两段，中间用草稿承接；AI 只往草稿里写字，老师确认后才变成错题。** 界面、结构、AI 三件事由这一刀同时解决。

如果只是在 v1 的录入页加个「AI 识别」按钮，把结果灌回表单，那么长表单还在、题目详情还是没有、AI 出错会直接脏库——三条诉求一条都落不了地。

## 二、总体架构（不换技术栈）

| 层 | v1 | v2 |
| --- | --- | --- |
| 运行时 | Node 26 LTS（本机 22 可跑）、Express 5、`node:sqlite` | 不变 |
| 前端 | 3 个 HTML + 1 个 343 行 `app.js` + 142 行 CSS | 6 个页面 + `public/js/` 按页拆模块 + 4 层 CSS；**仍无框架、无构建链、无新增运行时依赖** |
| 数据 | 7 张表 | 7 张 + 2 张（识别任务、识别草稿）+ `mistakes` 1 个溯源字段 |
| 后端 | 5 组路由、12 个接口 | + 2 组路由、9 个接口；`src/ai/` 从 1 个占位文件扩成 4 个模块 |
| 部署 | Dockerfile + compose | 不变，仅 compose 增加 AI 环境变量透传（默认空） |
| AI | 29 行占位 | OpenAI 兼容视觉接口，可插拔 provider，默认关闭，本地假 provider 可跑全流程测试 |

数据流：

```
手机拍照 ──> 前端压缩（原图另存） ──> POST /api/recognitions ──> images/ + recognition_jobs(queued)
                                                                    │
                                              进程内单并发 worker（可关闭）
                                                                    │
                                              OpenAI 兼容 vision（base64 压缩图）
                                                                    │
                                              normalize 清洗 / 置信度 / 白名单
                                                                    │
                                              recognition_drafts(pending)  ← 失败则 job=failed，原图保留
                                                                    │
                        收件箱：左原图带框 · 右逐题表单 · 改 / 删 / 合并 / 裁剪重识别
                                                                    │
                                     老师点「确认入库」（事务）
                                                                    │
                              mistakes(status='new') + image_path + 溯源字段
                                                                    │
                        题目详情（诊断 / 变式 / 证据） ──> 工作台复习 ──> A4 打印
```

**没有从 AI 直接指向 `mistakes` 的箭头。** 这是整个 v2 的结构底线。

## 三、信息架构（IA）重设计

### 3.1 导航按四个动作排，不按数据表排

| 路径 | 页面 | 只干一件事 | 对应动作 |
| --- | --- | --- | --- |
| `/` | 工作台 | 今天该干什么：待确认草稿 / 今日复习 / 逾期 / 待补定位，四个数字直达动作 | 练习 |
| `/inbox` | 识别收件箱 | 收照片、看 AI 草稿、逐题核对确认 | 收件 |
| `/mistake/:id` | 题目详情 | 一道题的一生：原图、诊断、变式、复习历史、掌握证据、五态进度 | 加工 |
| `/print` | 打印 | 选题（默认带今日复习）→ 预览 → 出 A4 纸 | 练习 |
| `/library` | 题库 | 按科目 / 状态 / 单元检索，批量补教材定位 | 归档 |
| `/settings` | 设置 | AI 开关状态、今日用量、教材版本、备份、健康 | 维护 |

v1 的 `/capture.html` 不再作为独立页面：`AGENTS.md` 要求废弃内容移入 `archive/`，故迁到 `archive/v1/capture.html` 留档，不删除。`/index.html`（新工作台）、`/print.html` 原地重写。页面数从 3 变 6，不是变复杂——**每个页面只做一件事，且任何一道题从收件到掌握都能顺着点下去**。

### 3.2 状态在界面上要看得见

题目详情页首固定一条五态进度：`待诊断 → 诊断中 → 纠错中 → 复习中 → 已掌握`，当前态高亮，并写清「还差什么才能往下走」（例如：学生结论未填、变式未审核、第 4 轮缺掌握证据）。v1 状态机逻辑全对，但界面只有一行小字，用户看不见，等于白做。

### 3.3 前端模块边界

```
public/
  css/tokens.css       设计令牌（唯一允许出现色值 / 字号 / 间距数字的文件）
       base.css         重置、排版、可访问性
       components.css   按钮、卡片、标签、表单、状态条、进度条、空态
       layout.css       顶栏、侧栏、栅格、三档断点
       print.css        A4（继承令牌，强制浅色）
  js/api.js            fetch 封装、统一错误
       ui.js            组件工厂（一律 textContent，禁止 innerHTML 拼用户输入）
       store.js         页面间共享的最小状态（当前题、收件箱计数）
       router.js        轻量路由与页面挂载，无第三方库
       pages/{workbench,inbox,detail,print,library,settings}.js
  icons.svg            内联 SVG 符号集，不引图标字体与外链
```

`public/app.js` 退役入 `archive/v1/`。新增 `scripts/check-ui.mjs`：静态检查页面必须含 `h1` / `nav` / `label`、CSS 不得出现硬编码十六进制色值（`tokens.css` 除外），纳入 `npm run check`。

## 四、视觉设计系统（「好看」怎么落地）

### 4.1 令牌分六组

| 组 | 内容 | 原则 |
| --- | --- | --- |
| 颜色 | 主色（深蓝）、辅色（青绿）、强调（暖橙）、语义（成功 / 警告 / 错误 / 信息）、中性 9 阶、表面 / 背景 / 边框 | 沿用项目既有的深蓝 / 青绿 / 暖橙配色取向，但补齐明度阶与语义色；浅色为默认，深色跟随系统 |
| 字号 | 12 / 14 / 16 / 18 / 22 / 28 / 36 七阶，配固定行高 | 手机上正文不小于 16px |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 七阶 | 所有 margin / padding / gap 只取这七个数 |
| 圆角 | 小 / 中 / 大 / 全圆四档 | 卡片与按钮统一 |
| 阴影 | 0 / 低 / 中 / 高四档 | 用阴影和留白分层，不靠到处加边框 |
| 动效 | 120ms / 200ms 两档，仅用于状态变化 | 尊重 `prefers-reduced-motion` |

### 4.2 组件清单（六个页面同一套）

按钮（主 / 次 / 危险 / 幽灵 / 图标）、卡片、状态标签（五态各一色 + 文字，不只靠颜色）、进度条、表单控件、空状态、骨架屏、错误条、Toast（分级）、识别框叠层、置信度标记、题卡（屏幕与打印共用数据源）。

### 4.3 布局与断点

| 视口 | 布局 |
| --- | --- |
| ≤ 640px（手机） | 单列，底部标签栏四项（工作台 / 收件 / 打印 / 更多），拍照按钮固定可达 |
| 641–1024px（平板） | 单列加宽，收件箱左图右表改为上下可切换 |
| ≥ 1025px（桌面） | 左侧固定导航 + 内容区，收件箱左图右表分栏，最大内容宽 1200px |

视觉层级硬规则：一屏内先看「今天该做什么」，其次数字，再次明细；任何页面不出现三级以上标题嵌套；打印页一律浅色。

### 4.4 静态视觉稿

`docs/design/ui-preview.html` 自包含，展示工作台、收件箱（含识别框与置信度）、题目详情五态、打印预览四处目标界面，并附令牌色板。它是**拍板用的靶子**，不含业务逻辑、不连数据库、不影响正在跑的 8080 服务。

## 五、数据模型变更（属 schema 变更，须先确认）

### 5.1 新增两张表

`recognition_jobs`（识别任务）：`id / image_path / status(queued|running|done|partial|failed) / provider / model / attempts / error_code / token_estimate / created_at / finished_at`。不存图片 base64、不存密钥、不存上游完整响应。

`recognition_drafts`（识别草稿）：`id / job_id / seq / bbox / subject / prompt / options / student_answer_draft / correct_answer_draft / question_type / knowledge_hint / has_figure / figure_desc / confidence(JSON) / uncertain(JSON) / raw_excerpt / status(pending|committed|discarded) / mistake_id / created_at / reviewed_at`。`UNIQUE(job_id, seq)` 防重复。

`mistakes` 加 `recognition_draft_id INTEGER`（溯源，可为 NULL，旧 19 题全为 NULL）。

### 5.2 迁移策略（v1 数据一条不丢）

- `migrate(db)` 保持 v1 的幂等 `CREATE TABLE IF NOT EXISTS`；新增 `migrateV2(db)` 单独负责加列。
- 加列前先 `PRAGMA table_info(mistakes)` 判断字段是否已存在，不存在才 `ALTER TABLE ... ADD COLUMN`，保证重复启动不报错。
- **迁移前强制跑一次 `npm run backup`**，把 `data/` 快照落到 `data/backups/`；迁移失败可整体回退。
- 迁移后回读：19 题 / 6 变式 / 19 图 / 25 节点计数不变，新表为空。
- 不删表、不重命名、不重建 `mistakes`；旧接口字段名全部保留。

## 六、接口清单

v1 的 12 个接口**全部保留不改语义**（v1 的 28 个测试就是回归基线）。新增 9 个：

| 方法 | 路径 | 职责 |
| --- | --- | --- |
| POST | `/api/recognitions` | 提交图片建 job，落原图，返回 `202 { jobId }` |
| GET | `/api/recognitions` | 收件箱列表（job + 其下草稿） |
| GET | `/api/recognitions/:id` | 轮询单个 job 状态与草稿 |
| POST | `/api/recognitions/:id/retry` | 失败任务重试（最多 2 次） |
| PATCH | `/api/recognition-drafts/:id` | 人工改草稿（只改白名单字段） |
| POST | `/api/recognition-drafts/:id/commit` | 事务内建 `mistakes(status='new')`，回写 `mistake_id` |
| POST | `/api/recognition-drafts/batch-commit` | 批量确认，逐条事务，部分失败不影响其余 |
| DELETE | `/api/recognition-drafts/:id` | 丢弃草稿（软标记 `discarded`，不删记录） |
| GET | `/api/ai/status` | 启用状态、今日已用 / 上限、最近失败原因；**不回密钥** |

`PATCH /api/mistakes/:id/diagnosis` 保持 `student_conclusion` 为空不许进 `correcting` 的闸门不变；AI 无绕过通道。

## 七、AI 模块拆分

| 文件 | 职责 | 关键点 |
| --- | --- | --- |
| `src/ai/provider.mjs` | 唯一对外 HTTP 出口 | OpenAI 兼容 `chat/completions` + `image_url`；`AbortSignal` 超时；只回原始文本；错误码归一化；密钥只在模块内从环境读 |
| `src/ai/prompt.mjs` | 识别提示词与输出契约 | 明确要求严格 JSON、多题切分、低把握留空、**不许给正确答案**；提示词与代码分离便于迭代 |
| `src/ai/normalize.mjs` | 清洗与校验（纯函数） | 白名单字段、bbox 校验、文本限长、置信度夹取、空题集判失败；零 IO，最好测 |
| `src/ai/jobs.mjs` | 进程内单并发 worker | 启动扫 `queued`、轮询间隔、超时重试、每日配额、优雅关闭；不引队列依赖 |
| `src/routes/recognitions.mjs` | 9 个接口 | 落图、建 job、草稿 CRUD、commit 事务闸门 |
| `src/routes/meta.mjs` | 增补 | `GET /api/ai/status` 并入（不新增第 7 组路由） |

`src/ai/client.mjs`（v1 占位）迁 `archive/v1/`，由上述模块取代。**任何 AI 模块都不 import 状态机、不 import `review_events`/`mastery_evidence` 写入路径**，从代码结构上隔离红线。

环境变量与失败降级矩阵详见 `docs/requirements/AI-vision-spec.md` 第五、七节。

## 十二、风险与对策

| 风险 | 对策 |
| --- | --- |
| 识别不准，老师反而更累 | 低置信度留空、逐题确认、原图常驻、一键退回手工；AI 不省掉核对，只省掉打字 |
