# 图片识别规格（AI 视觉草稿）

> 2026-11-05 补充。本文继续规范 OCR 与识别草稿；新增错步分析、支架问题及变式生成的规划见 [AI 学习闭环规格](AI-learning-loop-spec.md)。生成草稿须经教师确认，当前运行功能与计划分开。

| 项 | 值 |
| --- | --- |
| 版本 | v2.0 草案（待拍板） |
| 日期 | 2026-11-04 |
| 效力 | 低于 `AGENTS.md` 与 `PRD.md` 教学法硬约束；是 F15–F22 的技术展开 |
| 一句话 | 老师拍一张卷子照片，AI 负责「把图上的题拆开、把字认出来、填成草稿」；**能不能入库，由老师逐题点确认** |
| 关联 | `docs/requirements/PRD.md` 第十三至十九节、`docs/plans/2026-11-04-v2-plan.md` 第六至八节 |

## 一、先划死一条线

**AI 的产出永远是草稿，不是错题记录。**

照片进来 → AI 起草 → 老师看着原图逐题核对、改字、补教材定位 → 老师点「确认入库」→ 才生成 `mistakes` 记录，状态一律从 `new`（待诊断）开始。

AI 不写 `mistakes` 表，不写 `review_events`，不写 `mastery_evidence`，不改任何一道已有错题的状态。这条线不是保守，是 v1 教学法硬约束的延续：机器给的东西不自动生效。

## 二、真实输入长什么样（按这个设计，不按理想图片设计）

| 现实 | 设计应对 |
| --- | --- |
| 一张照片里常有 2–6 道题，混着题号、选项、图形、表格 | 一次识别输出 `questions[]`，每项带相对坐标框 `bbox`，不假定「一图一题」 |
| 有学生手写笔迹、红笔批改、涂改 | 只把笔迹识别为「学生答案草稿」，置信度单独标注，低了就留空让人填 |
| 有几何图、线段图、表格、拼音格、四线三格 | 不强行转文字，输出 `has_figure` + 文字描述；**原图始终随题保存**，打印时用原图 |
| 手机拍摄会倾斜、有阴影、局部虚焦 | 识别失败不猜、不生成半截题；整张退回，保留原图走手工录入 |
| 数学公式、分数、竖式 | 用纯文本 + 可读记法（如 `3/4`、`12×5`）起草，老师可改；不引 LaTeX 渲染依赖 |
| 语文的作文格、阅读理解长文段 | 允许长文本题干，但单题题干设长度上限，超了标「需人工核对」 |

**图片是录入的第一公民**：v2 允许「只有照片、一个字没打」就把题收进收件箱；文字是 AI 起草、人确认后补上的，不再是入库前置条件。

## 三、输出契约（服务端只认这个结构）

视觉模型被要求返回严格 JSON（`response_format` 不支持的 provider 由服务端从文本中提取第一个 JSON 对象，提取不到即判失败）：

```json
{
  "questions": [
    {
      "seq": 1,
      "bbox": [0.06, 0.10, 0.92, 0.28],
      "subject_hint": "math",
      "prompt": "把 3.6 米长的绳子平均分成 4 段，每段长多少米？",
      "options": [],
      "student_answer_draft": "0.8",
      "correct_answer_draft": null,
      "question_type": "应用题",
      "knowledge_hint": "小数除法",
      "has_figure": false,
      "figure_desc": "",
      "confidence": { "prompt": 0.94, "student_answer": 0.52, "subject_hint": 0.91 },
      "uncertain": ["student_answer"]
    }
  ],
  "page_note": "整页共识别 3 题"
}
```

服务端 `normalize.mjs` 做的清洗，一条都不能省：

| 规则 | 原因 |
| --- | --- |
| 只保留白名单字段，丢弃模型多给的一切内容 | 防止提示词注入把奇怪字段带进库 |
| `bbox` 必须是 4 个 0–1 的数字且 `x2>x1 / y2>y1`，否则置 `null` | 越界框会让前端裁剪错位 |
| 所有文本去首尾空白、限长、转义后按纯文本存 | 前端一律 `textContent`，不 `innerHTML` |
| `confidence` 每项夹到 0–1，缺失补 0 | 低置信度必须触发人工确认标记 |
| `correct_answer_draft` 即使模型给了也标 `needs_teacher_check` | 模型猜的答案不能当正确答案 |
| `questions` 为空、非数组、单题 `prompt` 为空 → 整任务判 `partial` 或 `failed` | 不生成半截题 |
| 原始响应用文本摘要存 `raw_excerpt`（截断、不含图片） | 便于排错，同时不把上游长文本全量留库 |

## 四、六步流程与状态

| 步 | 谁做 | 动作 | 落库状态 |
| --- | --- | --- | --- |
| 1 | 老师 | 手机拍照或选图，前端压缩后提交（长边 ≤1600px，JPEG 质量 0.82；**原图另存不压缩**） | `recognition_jobs.queued` |
| 2 | 服务端 | 落盘 `data/images/`，建 job，返回 `202` + jobId；前端不等 HTTP 长连接 | `queued` |
| 3 | 服务端 | 进程内单并发 worker 取 job，按 OpenAI 兼容 `chat/completions` 发文本提示 + `image_url`（base64 压缩图），带超时 | `running` |
| 4 | 服务端 | 解析 → 清洗 → 每题生成一条 `recognition_drafts`，标置信度与不确定字段 | `done` / `partial` / `failed` |
| 5 | 老师 | 收件箱里左看原图（带识别框）、右改表单，逐题确认；也可「重识别」：前端按框裁剪后作为新 job 再跑一次 | `draft.pending` |
| 6 | 老师 | 点确认 → 事务内创建 `mistakes`（`status='new'`）+ 关联原图 + 回写 `draft.mistake_id` | `draft.committed` |

**为什么用 job 表而不是一次 HTTP 请求等到结果**：手机切后台、网络抖动、云端模型慢（十几秒很常见）都会让长连接断掉。job 落库后，页面轮询 `GET /api/recognitions/:id`，断了重开还能接着看，失败能重试，且天然留调用痕迹用于配额统计。

状态机（job）：`queued → running → done | partial | failed`；`failed → queued`（人工重试，最多 2 次）。草稿：`pending → committed | discarded`。**没有「自动入库」这条边**。

## 五、Provider 抽象（不绑死一家）

统一走 OpenAI 兼容的 `chat/completions` + `image_url` 格式，这是国内多家视觉模型都支持的公共格式，切换只改环境变量：

| 变量 | 用途 | 默认 |
| --- | --- | --- |
| `AI_BASE_URL` | 兼容端点根地址 | 空（未配置即关闭） |
| `AI_API_KEY` | 密钥，只从环境读 | 空 |
| `AI_MODEL` | 视觉模型名 | 空 |
| `AI_TIMEOUT_MS` | 单次调用超时 | 30000 |
| `AI_MAX_IMAGE_BYTES` | 送上游的压缩图上限 | 2MB |
| `AI_DAILY_LIMIT` | 每日调用上限 | 30 |
| `AI_ENABLED` | 显式总开关 | `0` |

候选端点类型（**不写死厂商，不在文档里承诺某家的准确率与价格**）：阿里云百炼兼容模式（Qwen-VL 系列）、智谱 BigModel（GLM-4V 系列）、腾讯云混元视觉、任意 OpenAI 兼容网关。选型原则：中文手写与公式表现优先、支持 base64 图片输入、支持结构化输出。纯 OCR 接口不在 v2 范围内——它只能取字，读不懂「哪几行属于同一道题」和「这是图形不是文字」。

`src/ai/provider.mjs` 只暴露 `recognize({ imageBase64, mime, hint, signal })`，返回原始文本；换厂商不动业务代码。密钥不进代码、不进 git、不进日志、不进接口响应（`/api/ai/status` 只回「启用 / 未启用 / 今日已用 / 上限」）。

## 六、置信度怎么用（避免「看起来填满了其实全错」）

| 置信度 | 界面表现 | 入库规则 |
| --- | --- | --- |
| ≥ 0.85 | 字段正常显示，标「AI 起草」 | 老师仍需逐题点确认 |
| 0.60–0.85 | 字段黄底、标「请核对」 | 同上 |
| < 0.60 或模型自报 `uncertain` | 字段留空并标「AI 没把握，请手填」 | 该字段空着不许确认入库 |
| 整页识别失败 | 收件箱显示原图 + 「改为手工录入」入口 | 不生成任何草稿 |

**低置信度绝不自动填一个「看起来合理」的值**。宁可留空让人填，这是 v1「不造假数据」约束在 AI 场景的延伸。

## 七、失败降级矩阵（每一种都要有可走的路）

| 情况 | 系统行为 | 老师看到 |
| --- | --- | --- |
| 未配置 AI / 总开关关闭 | 不发起任何外部请求，图片照常收进收件箱，草稿为空白待手填 | 「AI 未启用，可手工录入，功能不受影响」 |
| 超时 / 网络断 | job 标 `failed`，指数退避重试 1 次，之后停 | 「识别超时，可重试或手工录入」 |
| 上游 429 / 配额用尽 | 当日不再发起新调用，job 标 `failed` 且不计费重试 | 「今日识别次数已用完，明早恢复」 |
| 返回非 JSON / 脏 JSON / 字段缺 | 清洗后判 `partial` 或 `failed`，**不把半截结果塞进草稿** | 「这次没读懂，建议重拍或裁剪单题重识别」 |
| 图片模糊 / 反光 | 模型返回空题集 → `failed` | 「没识别出题目，原图已保留」 |
| 切题切错（一题被拆两半 / 两题并一题） | 老师在收件箱合并或拆分草稿，或按框裁剪重识别 | 框可拖动、可删除，草稿可增删 |
| 上游异常但图片已入库 | 原图与 job 记录都保留，不删 | 收件箱始终能找到这张照片 |

**任何失败都不丢原图、不产生假题、不阻塞手工录入。** 这条比识别准确率更重要。

## 八、隐私与合规（启用前必须让你知情）

| 事实 | 说明 |
| --- | --- |
| 图片会离开局域网 | 云端视觉模型必然要把压缩图传到外部服务商；这是能力的前提，不是可以绕过的实现细节 |
| 内容可能含未成年人笔迹 | 学生手写答案、姓名、批改痕迹可能在照片里 |
| 默认关闭 | `AI_ENABLED=0` 且无密钥时不发任何外部请求；系统其余功能完全可用 |
| 显式启用 | 启用是设置页里一个明确的开关，旁边写清「开启即表示同意把题目照片发送给你配置的 AI 服务商」 |
| 最小化 | 只发压缩图，不发数据库内容、不发学生名单、不发其他题目 |
| 不留痕 | 不落密钥、不落上游完整响应、不落图片 base64 到日志；job 表只存状态、错误码、token 用量估算 |
| 不做的事 | 不做人脸识别、不做笔迹身份判断、不做学生画像、不把图片用于训练或二次分发 |

完全不接受图片外发时，**有等价退路**：收件箱里放原图 + 空白表单手工录入，v2 所有后续流程照常可用。AI 是加速器，不是必经关卡。

## 九、成本与配额

按 token 计费，图片分辨率直接影响用量，所以前端先压缩再上传。服务端硬约束：单 worker 单并发、每日调用上限、单图大小上限、超时、**同一 job 不重复扣费式重试**。设置页显示今日已用 / 上限，数据由 `recognition_jobs` 实时聚合，不另设计数表。

## 十、教学法红线（AI 一步都不能越）

| 红线 | 具体卡法 |
| --- | --- |
| 不判「已掌握」 | AI 不写 `mastery_evidence`，掌握仍须第 4 轮 + 五选一证据，由老师记录 |
| 不替学生说关键结论 | `student_conclusion` 字段永不来自 AI；为空不许进「纠错中」 |
| 不自动生效 | 所有 AI 草稿 `committed=0` 前不进 `mistakes`；变式建议仍走 `PATCH /api/variants/:id/review` |
| 不改写历史 | AI 不碰 `review_events` / `sessions` / 已有错题状态 |
| 不直接给学生答案 | 学生版打印接口永不返回 `correct_answer` 与 `scaffold_hint`（v1 已实现，v2 回归测试守住） |
| 不做激励与评判 | 不生成分数、评语、排名、对错标签给学生看 |

## 十一、测试要求（不接真实密钥也要跑通）

| 测试 | 断言 |
| --- | --- |
| 清洗器 | 脏 JSON、越界 bbox、超长文本、注入字段、低置信度、空题集，各自产出预期结果 |
| Provider mock | 成功 / 超时 / 429 / 非 JSON / 响应缺字段，通过本地假端点覆盖，不发外网 |
| 全流程 HTTP | 上传 → job → 草稿 → 人工改 → 确认 → `mistakes` 新增且 `status='new'` |
| 审核闸门 | 未经确认的草稿不产生错题；重复确认同一草稿只入库一次 |
| 红线 | 任一 AI 路径都不产生 `mastery_evidence` / `review_events`；学生版打印响应不含答案字段 |
| 未启用降级 | 清空环境变量时，上传照片仍能进收件箱，且没有任何外部请求 |
| 配额 | 达到上限后新 job 直接失败，且当日计数不出错 |

## 十二、v2 明确不做

自动判分、AI 直接讲题、AI 自动生成三层变式并免审核、整页扫描件批量 OCR 归档、离线本地视觉模型、语音输入、跨题知识点自动串联、家长端 / 学生端任何 AI 功能、把识别结果反向写回 `mistake-wiki/`。

这些不是「以后一定不做」，是**v2 不做**，避免范围失控。真要做，先改本文件再改代码。
