# v3 AI 学习闭环规格

日期为 2026-11-05。状态为需求编排已建立、功能待实现。当前运行版仍为 v2 + P16。本规格覆盖新增 AI 分析与备题范围，旧 OCR 规格继续用于识别环节。需求编号 F28–F39 与 PRD 第二十一节一致。

## 目标与人机分工

一个学生，老师操作系统，学生在纸上练习。老师拍照后，后台准备识别、分析候选、支架问题、相关题与变式；界面只突出关键核对与真实学习表现。AI 能推荐知识点与错因标签，学生无需先学会分类术语。AI 不替学生写关键结论，不产生掌握证据，不确认作答结果，不自动改变教学状态。

AI 输出经集中确认后生效。一组确认须显示组内题目、分析关键依据与未决问题；确认内容正确不等于学生已经通过。未确认数据不进入正式练习与学习统计。

## 流程与版本契约

照片→OCR 草稿→核对关键字段→分析候选→一次一问定位→生成/检索少量练习→质量校验→教师集中确认→固定纸面任务→登记真实结果→排期并备下轮→延迟新题验证→教师确认掌握。

可在 OCR 确认前预分析，但所有下游标记为暂定。题干、单位、否定词、必要图形、学生过程或目标能力改变后，未确认下游失效。已打印任务关联固定内容版本，不能被后台改稿覆盖。

## 数据模型设计边界

以下是待设计确认的概念实体，开发者先提交字段、约束、兼容、备份和恢复方案，经维护者明确确认再修改 schema。

| 概念 | 应保存的信息 | 一致性要求 |
| --- | --- | --- |
| AI 任务 | 输入版本、阶段、状态、尝试次数、额度、输出草稿、错误码 | 同题同版本同阶段幂等，重启能恢复 |
| 分析/练习候选 | 来源、目标能力、依据、题面、教师答案、审核版本与时间 | 与学生结论、作答结果及证据分开 |
| 学生验证事件 | 真实题/变式版本、日期、结果、帮助与学习周期 | 与质量审核分离，历史保留 |
| 练习批次 | 批次号、纸面序号、题目/变式/任务映射、内容快照 | 旧纸内容和题号不随新稿变化 |
| 掌握证据适用性 | 实际任务、观察、提示情况、时间、周期 | 旧证据不能凭历史总数证明复发后再次掌握 |

存量 reviewed/result 不直接转换为已验证的学习事件。缺明确历史来源的记录保留来源标记，要求新验证，不能补造历史。

## 学习规则

- 题目审核、学生验证、掌握判定分别处理。任何进入复习路径都检查真实关键结论及当前所需验证。
- 变式质量审核与学生作答分离（#67）：`PATCH /variants/:id/review` 只判题目成立与否；`PATCH /variants/:id/attempt` 登记学生本轮作答（independent / hinted / unmet / unjudged）。推进复习需三层质量 pass + 三层本轮 independent + 学生关键结论非空。存量 `reviewed/result` 不转换为验证记录；`unmet` 与质量 fail 是 #68 证据周期的回落边界。
- 证据无默认值，拒绝或明确忽略 wrong 携带的证据且不入库；接口采取的错误策略写明。重复提交继续用 due_on 与事务保证。
- 排期口径（#69 方案 A，已确认）：1-3-7-30 是相邻两次复习的间隔。第一次到第 4 轮只排 +30 天的长间隔任务；那次任务到期日已到或已过后真实完成（迟到不算违约，提前不算完成等待），且本轮有证据，才判已掌握。存量排期保留来源，不批量重排、不补历史。
- 计划结果为独立完成、提示后完成、未完成、暂未判断。API 编码、correct/wrong 兼容和排期映射需设计后确认；未判断不当错误，提示后成功不当独立成功。
- 做错默认回诊断，保留历史并突出当前最小补练。非知识原因不一律豁免，不因日历超期自动把已掌握降级。

### 复习登记契约（#68 已落地）

- `POST /api/reviews/:id/result` 在 `result=wrong` 同时带 `evidence_type` 时返回 400 `EVIDENCE_NOT_ALLOWED`，整个请求不落库：不写 `review_events`、不写 `mastery_evidence`、不改 `mistakes`。选择「拒绝」而不是「静默忽略」——忽略会让老师以为证据记上了，而证据正是以后判掌握的依据。
- 本轮证据指最近一次回落之后录入的 `mastery_evidence`。回落取较晚者：`review_events.result='wrong'` 的 `done_at`，或 `variants.result='fail'` 的 `attempted_at`。旧证据保留在库、照常展示，但不参与本轮 `canMaster` 计算。
- 两个登记入口（看板到期卡、工作台今日列表）共用同一套约束：证据下拉第一项为空占位且不预选；只有「做对」才允许带证据；不代填证据说明，写什么由老师记录。
- `due_on` 判重、事务包裹与「写成功读回失败」提示保持不变。

## AI 输出与校验

分析候选给目标能力、具体错步、依据、待验证假设及一个问题。过程不足时表明不确定，歧义时给少量可区分假设。学生说的话由老师记录，可后续修正分析。

先查本地已确认相关题，给来源题号及保持的能力。缺合适材料再生成并标记 AI 草稿；无外部检索就不声称来源教材。每轮少量候选，数量与预算可控。

候选题包含目标能力、保持/改变要素、题干、必要图形或材料、教师答案和评分要点。数学检查计算和单位，语文检查文本依据和合理表述，英语检查语言功能和可接受答案。模型二次校验不保证正确，教师仍确认。缺图、矛盾条件及明显超学段停在待处理。

学生版只投影干净题面。原卷含作答或红笔时不自动上纸；必要图片须核对，不能直接丢图。原图仍作为教师侧只读材料保存。

### 学生版出图契约（#70 已落地）

- 出图优先级：老师上传的净图（`clean_image_path`）> 老师确认无作答痕迹的原图（`sheet_image_ok=1`）> 不出图。原图本身默认不上纸，只在教师侧详情保留，只读不删。
- 需图判定：识别草稿 `has_figure=1`，或题干为空（图即题）。需图但没有可用净图且无几何图时，该题进打印响应的 `blocked` 清单，明确阻止成卷，不静默印成无图题。
- 上纸确认是显式教师事件：`POST /mistakes/:id/sheet-image` 支持上传净图、确认原图、撤销；图片路径只能由服务端生成，不接受调用方指定。存量 `sheet_image_ok` 全默认 0，逐题确认。

## 后台恢复与界面

阶段失败可就地重试，额度用尽显示待处理，AI 关闭仍可手工完成。环境变量密钥与外发开关沿用现有边界，开发测试只用假 provider。

五态看板保留，顶部今日动作按真实任务派生。AI 任务状态附在题卡，与教学状态分开。看板和今日列表共用结果登记。写成功读回失败提示已保存，后续只重读。

## 验收与试运行

开发先写红灯测试，再实现；npm run check、npm test 全绿并以虚构数据真实回读。视觉验收沿用方案 B。完整案例至少包括审核不等于作答、空结论不能跳过、wrong 不写证据、旧证据不自动适用、带答案原图不自动上纸、OCR 改动使旧稿失效、重启恢复不重复任务、部分完成仍有待办。

一个学生先记录操作基线，再小规模试用。看教师主动操作时间、AI 草稿可用率、延迟新题独立完成、帮助依赖及反复错误。分子分母和日期完整，未做不算错。两周体验评估不能代替 30 天验证。实际试用未完成时保持该验收开放。
