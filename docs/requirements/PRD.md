## 一、一句话目标

做一个**放在家里 NAS 上、一直开着的网页**，老师随手把学生错题拍进去，系统每天自己把该复习的题排出来，老师打印成纸质题目给学生做，把做对做错记回去，直到有真实证据证明学生真会了，才算过关。

关键词是**自己往前走**。不用老师记得「今天该打开系统看看」，系统常开，每天自己算。

## 二、为什么做这个（真实痛点，不是想象的需求）

原来的做法是 `mistake-wiki`：一堆 Markdown 文件 + Python 脚本，规则写得很全，但**只有人打开文件夹时才检查复习日期**。实测结果：

| 实测项 | 数值 |
| --- | --- |
| 录入错题 | 19 道（数学 16、语文 3、英语 0） |
| 已掌握 | 1 道 |
| 复习逾期 | **15 道，逾期约 5 个月**（应复习日 2026-05-28 / 06-03，今天 2026-11-04） |
| 教材/学习文档 | 299 份，零真实学生试运行 |

根因不是「缺规则」，是**缺一个不用人记、自己每天推进的常驻服务**。换任何技术栈都救不了「人不打开，系统就不存在」这件事。本项目的价值全部押在这一条上。

另外三个旧库的坑，第一版必须堵住：

1. 看板数字靠手写，19 道题就出现「虚报已掌握 6 道」。新系统**所有数字实时从数据库算**，不许手填。
2. 两套纠错流程并存且打架（旧流程 AI 直接给病因，新流程要学生自己说出来）。新系统**只保留一套**。
3. 变式题硬编码在脚本里、语文英语近乎空白。新系统变式由老师录入并经审核，且**三科规则分开**，不把数学那套套到语文英语上。

## 三、给谁用 / 不给谁用

| 项 | 结论 |
| --- | --- |
| 使用者 | 老师本人，用自己的电脑 / 手机 / 平板浏览器，在家里局域网或 Tailscale 内访问 |
| 学生 | **不碰系统**。学生拿到的是 A4 打印纸，在纸上做题 |
| 家长 | 不是必需环节。本地学情以留守儿童为主，家长多在异地，不能把「家长每天配合」设成流程前置条件 |
| 不做 | 公网入口、账号登录、多老师协作、学生在线答题、家长端、小程序 |

## 四、老师一天怎么用（场景）

1. 改作业/改试卷，看到一道典型错题，手机打开 `http://NAS地址:8080`，点「录入」，拍照，选科目、填题干，提交。可以连着录好几题，不用一题一页。
2. 系统把题记为「待诊断」。老师随手写下：这题卡在哪（一次只问学生一个点）、错因属于哪一类。学生自己说出关键结论后，老师把那句话记进系统。
3. 老师给这题补三道变式题：换数字、换角度、换场景。提交后**必须自己点审核**才生效（AI 以后给的建议也走这一步，不能直接生效）。
4. 第二天起，系统每天自动算：哪些题今天该复习了，列在首页「今日复习」。
5. 老师勾选要练的题，点打印，出 A4 纸，每道题和它的变式**不跨页断开**。学生版**不带答案**。
6. 学生做完，老师在网页上点「做对 / 做错」。做对就按 1、3、7、30 天往后排；做错就打回诊断，从头来。
7. 做对第 4 轮，还不行——必须再补一条**掌握证据**（复述 / 同结构变式 / 间隔提取 / 说出检查方法 / 讲给别人听，五选一），才标记「已掌握」。

## 五、功能需求

| F02 | P0 | 支架式诊断 | 能记录「一次一个维度的定位问题」和「学生自己说出的关键结论」；结论为空时系统不允许把状态推到「纠错中」 |
| F03 | P0 | 三层变式 | 每题可录 surface / structure / context 三道；**未审核不生效**；任一层做错打回诊断；三层全过才进复习队列 |

| F08 | P0 | 只读导入旧数据 | 19 道旧题、6 条变式、19 张图片、25 个教材单元节点一次性导入；旧库一个字节不改；重复执行不产生重复数据 |

## 六、教学法硬约束（大白话版，代码必须服从）

| 约束 | 意思 | 代码里怎么卡住 |
| --- | --- | --- |
| 支架式引导 | 不直接给答案；一次只问一个点；学生没说出思路前不纠正；关键结论必须从学生嘴里出来 | 学生版打印页不含答案与提示；`student_conclusion` 为空不许进「纠错中」 |
| 真实掌握 | 一次做对不算会 | 掌握闸门 = 第 4 轮 + 1 条证据，两个条件硬编码在状态机 |
| 迟到不重置 | 忘了三个月不惩罚，不从头开始 | 状态推进函数不读应复习日，只看当前轮次 |
| 三科分开 | 语文英语不是「数学换了层皮」 | 错因字典和变式方向按科目分列，不共用 |
| 教师审核 | AI/机器给的东西不自动生效 | 变式 `reviewed=0` 不参与状态推进 |
| 不造假数据 | 看板只说真话 | 无计数表，全部 `SELECT COUNT` 实时算 |
| 不做激励工具 | 不做打卡、排名、积分、惩罚 | 界面无此类元素 |

## 十、数据来源与边界

- `/Users/walt/codes/my/mistake-wiki/` 是**只读数据源**：绝不写入、不修改、不删除、不移动。
- 只读实测发现（交接文档未记载，已写进施工单）：
  1. 旧 19 题全是**三年级下册**，教材骨架是**四年级上册**，两者挂不上；
  2. 旧题 frontmatter **没有教材定位字段**，补不出来；
  3. 三层变式仅 2 道题有，且只在正文自由文本里，混着历史作答与「通过」标记；
  4. 19 张图片全部存在；15 道逾期约 5 个月，导入首日会全量出现在「今日复习」。
- 导入时：旧题不挂四上节点、标记待补；变式只导题干，不把历史作答伪造成本系统复习事件；`variant_count` 不导入，改实时统计。

## 十一、决策记录（本轮按授权自主定稿，共 9 项）

| # | 议题 | 定稿 |

另两处实现层修正（比原施工单更简单可靠，已审核）：

- **图片上传改 JSON + base64**，不手写 multipart 解析。Express 5 自带 JSON 解析，图片经 dataURL 提交，服务端解码落盘；省掉边界解析、二进制截断、大文件流式处理三类坑，且不新增依赖。
- **日期计算固定 Asia/Shanghai**（`src/lib/dates.mjs`），不靠进程 `TZ` 环境变量，避免 NAS 设成 UTC 时「今日」差一天。

## 十二、术语表（给外行）

| 词 | 意思 |
| --- | --- |
| 错题状态 | 一道题当前处在：待诊断 → 诊断中 → 纠错中 → 复习中 → 已掌握 |
| 轮次 | 做对一次记一轮，按 1 天、3 天、7 天、30 天拉开间隔，最多 4 轮 |
| 变式 | 同一考点换皮的题：换数字（表面）、换角度（结构）、换场景（情境） |
| 掌握证据 | 证明「真会了」的五种动作之一，不是「又做对一次」 |
| 支架式引导 | 老师只搭台阶不给答案，学生自己说出关键结论 |
| 迟到不重置 | 忘了很久不罚，不把轮次清零 |
| WAL | SQLite 的一种写日志方式，读写不容易互相卡住 |
| 常驻服务 | 一直开着、到点自己干活的程序，不用人打开网页 |
