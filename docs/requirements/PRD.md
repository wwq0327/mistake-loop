## 一、一句话目标

做一个**放在家里 NAS 上、一直开着的网页**，老师随手把学生错题拍进去，系统每天自己把该复习的题排出来，老师打印成纸质题目给学生做，把做对做错记回去，直到有真实证据证明学生真会了，才算过关。

关键词是**自己往前走**。不用老师记得「今天该打开系统看看」，系统常开，每天自己算。

## 二、为什么做这个（真实痛点，不是想象的需求）

原来的做法是 `mistake-wiki`：一堆 Markdown 文件 + Python 脚本，规则写得很全，但**只有人打开文件夹时才检查复习日期**。实测结果：

| 实测项 | 数值 |
| --- | --- |
| 录入错题 | 19 道（数学 16、语文 3、英语 0） |
| 已掌握 | 1 道 |
| 复习逾期 | **15 道，逾期约 5 个月**（应复习日 2026-05-28 / 06-03，今天 2026-11-04） |
| 教材/学习文档 | 299 份，零真实学生试运行 |

根因不是「缺规则」，是**缺一个不用人记、自己每天推进的常驻服务**。换任何技术栈都救不了「人不打开，系统就不存在」这件事。本项目的价值全部押在这一条上。

另外三个旧库的坑，第一版必须堵住：

1. 看板数字靠手写，19 道题就出现「虚报已掌握 6 道」。新系统**所有数字实时从数据库算**，不许手填。
2. 两套纠错流程并存且打架（旧流程 AI 直接给病因，新流程要学生自己说出来）。新系统**只保留一套**。
3. 变式题硬编码在脚本里、语文英语近乎空白。新系统变式由老师录入并经审核，且**三科规则分开**，不把数学那套套到语文英语上。

## 三、给谁用 / 不给谁用

| 项 | 结论 |
| --- | --- |
| 使用者 | 老师本人，用自己的电脑 / 手机 / 平板浏览器，在家里局域网或 Tailscale 内访问 |
| 学生 | **不碰系统**。学生拿到的是 A4 打印纸，在纸上做题 |
| 家长 | 不是必需环节。本地学情以留守儿童为主，家长多在异地，不能把「家长每天配合」设成流程前置条件 |
| 不做 | 公网入口、账号登录、多老师协作、学生在线答题、家长端、小程序 |

## 四、老师一天怎么用（场景）

1. 改作业/改试卷，看到一道典型错题，手机打开 `http://NAS地址:8080`，点「录入」，拍照，选科目、填题干，提交。可以连着录好几题，不用一题一页。
2. 系统把题记为「待诊断」。老师随手写下：这题卡在哪（一次只问学生一个点）、错因属于哪一类。学生自己说出关键结论后，老师把那句话记进系统。
3. 老师给这题补三道变式题：换数字、换角度、换场景。提交后**必须自己点审核**才生效（AI 以后给的建议也走这一步，不能直接生效）。
4. 第二天起，系统每天自动算：哪些题今天该复习了，列在首页「今日复习」。
5. 老师勾选要练的题，点打印，出 A4 纸，每道题和它的变式**不跨页断开**。学生版**不带答案**。
6. 学生做完，老师在网页上点「做对 / 做错」。做对就按 1、3、7、30 天往后排；做错就打回诊断，从头来。
7. 做对第 4 轮，还不行——必须再补一条**掌握证据**（复述 / 同结构变式 / 间隔提取 / 说出检查方法 / 讲给别人听，五选一），才标记「已掌握」。

## 六、教学法硬约束（大白话版，代码必须服从）

| 约束 | 意思 | 代码里怎么卡住 |
| --- | --- | --- |
| 支架式引导 | 不直接给答案；一次只问一个点；学生没说出思路前不纠正；关键结论必须从学生嘴里出来 | 学生版打印页不含答案与提示；`student_conclusion` 为空不许进「纠错中」 |
| 真实掌握 | 一次做对不算会 | 掌握闸门 = 第 4 轮 + 1 条证据，两个条件硬编码在状态机 |
| 迟到不重置 | 忘了三个月不惩罚，不从头开始 | 状态推进函数不读应复习日，只看当前轮次 |
| 三科分开 | 语文英语不是「数学换了层皮」 | 错因字典和变式方向按科目分列，不共用 |
| 教师审核 | AI/机器给的东西不自动生效 | 变式 `reviewed=0` 不参与状态推进 |
| 不造假数据 | 看板只说真话 | 无计数表，全部 `SELECT COUNT` 实时算 |
| 不做激励工具 | 不做打卡、排名、积分、惩罚 | 界面无此类元素 |

# 以下为 v2 增量（已定稿并实现）

## 十三、v2 要补的三条，以及它们之间的结构关系

v1 跑通了闭环，但它是「照数据库表排界面」：录入页 = 一张 `mistakes` 表的字段清单，复习页 = 一次 `SELECT`，打印页 = 一次聚合。三页平级，一道错题的一生被切成三段，老师得在脑子里拼起来。

v2 改成**照老师的活儿排界面**，四个动作：

| 动作 | 老师心里的话 | 系统给的页面 |
| --- | --- | --- |
| 收件 | 「先拍下来，回头再说」 | 识别收件箱 |
| 加工 | 「这题卡在哪、学生怎么说、变式补什么」 | 题目详情 |
| 练习 | 「今天该练哪些、出纸、记做对做错」 | 工作台 + 打印 |
| 归档 | 「找一道旧题、把缺的教材定位补上」 | 题库 |

**结构上的关键一刀：把「一次提交一整张表」拆成「先收件、后加工」两段，中间用草稿承接。**

这一刀同时解决三件事：

1. 界面好看了 —— 录入页不再是 12 类字段的长表单，收件页只做「拍照 + 看结果」；
2. 结构合理了 —— 题目详情有了自己的位置，五态进度、复习历史、掌握证据各归其位；
3. AI 终于放得进来了 —— AI 本来就只能产出草稿，不能产出成品；有了草稿层，AI 是自然插进来的能力，不是硬贴上去的按钮。

**反过来说：如果只在 v1 的录入页加一个「AI 识别」按钮，把识别结果直接灌进表单，三条诉求一条都解决不了，还会把数据搞脏。**

## 十四、v2 场景（替代第四节的操作路径）

1. 改试卷，看到一页有三道典型错题。手机打开系统 →「识别收件箱」→ 拍照，提交后即可关掉页面。系统把原图留下，AI 在后台拆成三条草稿；没配 AI 也能做，只是草稿空白等人填。
2. 有空时打开收件箱：左边原图带识别框，右边三条草稿逐条对。AI 没把握的字段留空标黄，老师改字、补科目、补教材单元，合并切错的题、删掉不要的题，逐条点「确认入库」。
3. 入库的题状态是「待诊断」。点进题目详情，按支架式引导一次只问一个点，记下学生自己说出的关键结论，补三道变式并逐条审核。页首有五态进度条，看到它走到哪一步。
4. 工作台首页显示今天该干什么：待确认草稿几张、今日复习几题、逾期几题、待补教材定位几题。点进去就是对应动作，不需要记菜单。
5. 勾选要练的题 → 打印页预览 → 出 A4 纸（学生版仍无答案）。做完回工作台点「做对 / 做错」，系统按 1-3-7-30 自己往后排。
6. 第 4 轮做对仍不算过，补一条掌握证据才标「已掌握」。这一条 v1 已经写死在状态机里，v2 只是让它**在界面上可见**。

## 十六、AI 能力边界（写给外行，也写给开发）

详细技术规格见 `docs/requirements/AI-vision-spec.md`。这里只列**能**与**不能**：

| AI 能做 | AI 不能做 |
| --- | --- |
| 从照片里把题拆开 | 判定学生「已掌握」 |
| 把印刷体、部分手写转成文字草稿 | 生成掌握证据、替学生说出关键结论 |
| 起草科目、题型、知识点、学生答案 | 直接写进错题库（必须老师确认） |
| 标出「这题有图，长这样」并保留原图 | 把图形凭空重画成「标准答案图」 |
| 说「这个字段我没把握」并留空 | 没把握时猜一个看起来合理的值 |
| 后台排队、失败重试、用完当日配额就停 | 自动改写历史复习记录、变式审核结果 |

**一条红线贯穿全部**：AI 是速记员，不是老师，更不是判卷人。v1 第六节七条教学法硬约束，v2 一条不减。

另外一件必须让你知道的事：**云端视觉识别意味着题目照片会离开家里局域网，发到你配置的服务商**。照片里可能有学生笔迹。所以 AI 默认关闭，启用是设置页里一个写明后果的显式开关，且永远留一条完全不外发、纯手工的等价路径。

## 十七、UI 与结构的验收（不写「好看」这种没法判的词）

「好看」没法写进验收，所以拆成可逐条核对的硬指标：

| # | 可判定标准 |
| --- | --- |
| U1 | 存在令牌文件，颜色 / 字号 / 间距 / 圆角 / 阴影 / 动效各有命名变量；全部页面只引用变量，不写死十六进制色值 |
| U2 | 同一类元素（卡片、按钮、标签、表单、状态条）在六个页面里外观一致，由同一组组件类实现 |
| U3 | 页面有明确视觉层级：一屏之内先看到「今天该做什么」，其次是数字，再次是明细；不靠堆边框分区 |
| U4 | 三档视口逐页检查：无横向滚动、无文字截断、无按钮被遮挡、触控目标 ≥44px |
| U5 | 四种状态都有明确呈现：加载、空、错误、成功；错误要说人话并给下一步动作 |
| U6 | 五态进度在题目详情可见，当前状态、下一状态、还差什么条件，一眼能读出 |
| U7 | 打印页与屏幕页共用同一套题卡数据，打印时自动切浅色、隐藏导航，A4 不跨页断题 |
| U8 | 界面无打卡、排名、积分、惩罚、勋章一类激励元素（v1 硬约束） |

另外交一份**静态视觉稿** `docs/design/ui-preview.html`，随时可以打开看目标长什么样，不用靠想象判断「好不好看」。视觉稿不是成品，不含业务逻辑，不影响正在运行的服务。

## 二十、v2 术语补充

| 词 | 意思 |
| --- | --- |
| 草稿 | AI 识别出来、还没被老师确认的题，不算正式错题，不参与复习与统计 |
| 收件箱 | 放照片和草稿的地方，相当于「先拍下来回头再说」的篮子 |
| 识别框 | 照片上圈出「这一块是第几题」的方框，用来对照和裁剪重识别 |
| 置信度 | AI 对自己认出来的字有多大把握；把握小就留空让人填，不猜 |
| provider | 具体提供 AI 识别服务的厂商接口，可换，不绑死 |
| 设计令牌 | 把颜色、字号、间距这些起好名字统一存一处，所有页面引用，改一处全站生效 |
| 任务动线 | 按「老师干活的顺序」排页面，而不是按数据库表排页面 |
| 溯源字段 | 正式错题上记一句「它来自哪条草稿」，方便回查 |



## 二十一、v3 AI 学习闭环增量（2026-11-05，计划中）

使用者已确认主要跟踪一个学生，并要求尽量由后台 AI 承担题目分析、相关题和同题型出题。延续方案 B，老师完成拍照、关键核对与学习表现登记，学生继续纸面练习。新增边界与契约见 [AI 学习闭环规格](AI-learning-loop-spec.md)，实施依赖见 [施工计划](../plans/2026-11-05-ai-learning-loop-plan.md)。

| 编号 | 优先级 | 需求 | 验收摘要 |
| --- | --- | --- | --- |
| F28 | P0 | 真实学生验证 | 质量审核与作答分离，所有推进路径检查关键结论，存量不造历史 |
| F29 | P0 | 本轮有效证据 | 无预选、wrong 不入证据、历史证据保留且适用性有依据 |
| F30 | P0 | 真实延迟验证 | 日期含义先明确并确认，长间隔任务实际发生才满足对应闸门 |
| F31 | P0 | 干净学生题面 | 原图保留，含答案/批注原图不默认上纸，必要净图不丢 |
| F32 | P0 | 后台串接 | 识别、分析、备题分阶段，版本失效、幂等、重启恢复与预算受控 |
| F33 | P0 | AI 定位与支架 | 分析引用证据，缺信息用假设，一次问一个维度，教师记录学生原话 |
| F34 | P0 | 检索与三科出题 | 本地来源可追溯，三科校验各自实现，教师答案与学生题面分离 |
| F35 | P0 | 集中核对与今日动作 | 拍照后后台接续准备，确认动作集中，真实待办直达任务 |
| F36 | P0 | 固定纸面任务 | 批次号、纸面序号、内容快照、任务映射与部分完成一致 |
| F37 | P0 | 学习表现与下轮 | 独立/提示后/未完成/未判断有不同后续，自动备下轮新题 |
| F38 | P1 | 有依据的周复盘 | 统计有分母和日期，AI 建议引用实际题号与事件，不排名 |

AI 边界扩展为生成可审核草稿，正式入库、学生结论、证据与掌握继续由真实教师确认事件驱动。旧“AI 只做速记员”的范围对新增分析/出题被本节扩展。原版审核与学生验证混用、日期轮次和证据历史复用属于待修正项，不能按历史“已交付”描述跳过。

本节授权需求设计与常规开发任务编排。schema 变更、数据迁移及密钥配置仍须另行明确确认；具体排期日期政策和结果类别兼容须先提交设计。未确认前保留当前运行规则，不在界面偷偷把新结果类别映射为 correct。
