## 二、你的三条意见，落到代码上分别是什么

### 1. UI 要好看 —— 现状不是「丑一点」，是根本没有设计系统

| 实测 | 位置 |
| --- | --- |
| 全部视觉规则只有 142 行 CSS，11 个硬编码颜色变量，没有字号阶、间距阶、层级、阴影、动效规范 | `public/style.css` |
| 布局只有一处 `max-width: 900px` + `flex-wrap`，没有断点、没有栅格、没有侧栏，手机上是「同一张长表单往下拉」 | `public/style.css:44` |
| 所有卡片长得一样：白底、1px 边、10px 圆角，靠文字区分，没有视觉层级 | `public/style.css:73` |
| 缺加载态、骨架屏、空状态设计、错误态、操作反馈层级；出错一律弹底部 toast | `public/app.js:32` |
| 页面无品牌识别、无留白节奏、无深浅色适配 | 三份 HTML |

这些都是「功能优先」阶段的正常产物。要好看，不是调几个颜色，是**先定一套令牌（颜色 / 字号 / 间距 / 圆角 / 阴影 / 动效），再让所有页面服从它**。

### 2. 结构要合理 —— 这是三条里最根本的一条

v1 的界面是**照着数据库表和接口顺序排的**，不是照着老师的活儿排的：

| 现象 | 证据 | 后果 |
| --- | --- | --- |
| 一个页面塞了科目、教材、题干、答案、拍照、错因、定位问题、学生结论、三道变式，共 12 类字段 | `public/capture.html` 100 行 | 录一题要滚一整屏，手机上几乎不可用 |
| 后端有 `GET /api/mistakes/:id` 详情接口（带变式、复习事件、会话、掌握证据），前端**没有任何详情页**用它 | `src/routes/mistakes.mjs:93` vs `public/app.js` | 一道题的一生被切成三段，散在三个页面，老师要在脑子里拼 |
| 五态机、轮次、掌握证据这些核心状态，界面上只有一行小字，看不到进度也跳不过去 | `public/app.js:97` | 系统最值钱的「状态自己往前走」，用户反而看不见 |
| 三页平级导航：今日复习 / 录入 / 打印 | 三份 HTML 的 `nav` | 没有「收件 → 加工 → 练习 → 归档」的任务动线 |
| 343 行单文件 JS 承担三页全部渲染与交互，无组件、无模块边界 | `public/app.js` | 再加 AI 界面会直接失控 |

一句话：**v1 把「一次提交一整张表」当成录入，把「一道错题的一生」藏在数据库里。** 结构重做的核心不是多加几个页面，是把录入拆成「先收件、后加工」两个阶段，中间用草稿承接。这条改动同时把「结构合理」和「AI 识别」两个诉求合一了——AI 本来就只能产出草稿，不能产出成品。

### 3. 要借助 AI 识别图片 —— 现状是零，不是半成品

| 实测 | 证据 |
| --- | --- |
| AI 全部实现只有 29 行，是一个往自定义 `/analyze` 地址 POST JSON 的占位函数，未配置时返回 `disabled` | `src/ai/client.mjs` |
| 没有图片输入通道、没有视觉模型协议、没有 provider 抽象、没有草稿表、没有识别界面、没有重试与配额 | 全项目检索 |
| **图片是文字题干的附件**：`prompt`（题干）必填，`image` 可选；没手打题干就存不进题 | `src/routes/mistakes.mjs:26-27`、`public/capture.html:44-55` |
| 上传通道只支持单张、单个 `<input type="file">`，无多图、无切题、无框选、无预览裁剪 | `public/capture.html:54`、`public/app.js:181` |
| 界面上唯一的 AI 痕迹是「待审核变式」区块的一句说明文字 | `public/index.html:29-31` |

**这一条和你说的场景正相反**：你说「很多时候需要的是一张图片，不是复制一段文字」；v1 是「先有文字，图片可有可无」。所以要改的不是「加个 AI 按钮」，是**把图片变成录入的第一公民，文字由 AI 起草、由人确认**。

另外，`AGENTS.md` 第 36-38 行把「OCR 自动切题」写进了「第一版明确不做」，PRD 第八节也写了「OCR 自动切题」不做。这是 v1 按当时边界做的，不是疏漏；现在目标变了，**必须先把这两处约束改掉再动代码**（见施工单第十三节）。

## 三、不是问题、不要动的部分

下面这些是 v1 做对了的，v2 只在其上加层，不推倒：

- 五态机、1-3-7-30、迟到不重置、掌握证据闸门、教师审核闸门（`src/state-machine.mjs`）
- 7 张表的实时聚合，无计数表，不虚报（`src/routes/meta.mjs`）
- 学生版打印永不返回答案与提示（`src/routes/print.mjs`）
- 常驻调度每日留痕 + 实时查询（`src/scheduler.mjs`）
- 旧库只读导入幂等、备份恢复演练（`scripts/`）
- 零构建链、单运行时依赖 Express 5、Node 内置 `node:sqlite`（`package.json`）

**教学法硬约束一条都不能为 AI 让路**：AI 不能判「已掌握」、不能生成掌握证据、不能替学生说出关键结论、不能自动生效、不能改写历史复习记录。
